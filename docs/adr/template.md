# ADR NNN: Short title in the form of the decision

Status: Proposed | Accepted | Superseded by ADR NNN
Date: DD Month YYYY

## Context

What forced a decision. The constraint, the pressure, the thing that would go wrong if nobody chose. Include the numbers that mattered: data sizes, latency budgets, costs, counts from the real database. Someone reading this in a year should be able to tell whether the context still holds.

## Decision

What was chosen, in the present tense and as an instruction to the code: "the API does X". One paragraph, then the specifics that follow from it.

## Alternatives considered

One heading per alternative that was genuinely on the table, each saying what it was and why it lost. An alternative nobody would pick does not belong here. If an option lost on something other than merit, such as time or cost, say so plainly.

## Consequences

What the project now has to live with, good and bad. The bad half is the point: extra moving parts, new failure modes, work this forces on future changes. Name the failure modes the code has to handle.

## Revisit when

The conditions that would make this decision wrong. Leave it out only when nothing would.
